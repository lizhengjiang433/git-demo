## 函数

- $(foreach var,list,text)

> for each var in list, change it to text。

对list 中的每一个
元素，取出来赋给var，然后把var 改为text 所描述的形式。

```
objs := a.o b.o
dep_files := $(foreach f, $(objs), .$(f).d) // 最终 dep_files := .a.o.d .b.o.d
```

- $(wildcard pattern)

```
src_files := $( wildcard *.c) // 最终 src_files 中列出了当前目录下的所有.c 文件
```

- $(filter pattern...,text)

把text 中符合pattern 格式的内容，filter(过滤)出来

```
obj-y := a.o b.o c/ d/
DIR := $(filter %/, $(obj-y)) //结果为：c/ d/
```

- $(filter-out pattern...,text)

把text 中符合pattern 格式的内容，filter-out(过滤)出来

```
obj-y := a.o b.o c/ d/
DIR := $(filter-out %/, $(obj-y)) //结果为：a.o b.o
```

- $(patsubst pattern,replacement,text)

找`text’中符合格式`pattern’的字，用`replacement’替换它们。
`pattern’和`replacement’中可以使用通配符。

```
subdir-y := c/ d/
subdir-y
:= $(patsubst %/, %, $(subdir-y)) // 结果为：c d
```

> 找出所有以 `/` 结尾的词
>
> 把结尾的 `/` 去掉

# 文件IO

## 分类

标准IO：fopen/fread/fwrite/fseek/fflush/fclose

系统调用IO：open/read/write/lseek/fsync/close

标准IO 的内部，会分配一个用户空间的buffer，读写操作先经过这个
buffer。在有必要时，才会调用底下的系统调用IO 向内核发起操作

`标准 I/O` 由于有用户态缓冲、可能自动刷新、还可能带锁，所以**时延不够确定**，不适合强实时、低延迟、要求确定性的场景

`系统调用 I/O` 更直接，控制粒度更细，**更接近底层**，通常比标准 I/O 更适合需要精细控制的场景

这里打开的就不是普通文件，而是**字符设备**，最终会走到对应驱动。

**和内核“连接”的状态在哪里？**

不在用户代码里，而在内核里和 `fd` 里：

- 用户态拿到的是 `fd`
- 内核里会记录这次打开的对象
- 后续 `read(fd, ...)`、`write(fd, ...)` 都通过这个 `fd` 去找对应的内核对象

`open()` 成功后，内核会建立一个“打开文件对象”

这个对象和进程里的 `fd` 绑定

以后读写时，内核就知道你在操作哪个文件/设备

```

复制文件描述符，就是两个文件句柄指向同一个文件描述符，

> oldfd：被复制的文件句柄
> newfd：复制得到的文件句柄

> dup2 可以指定复制得到的文件句柄为newfd，

# Framebuffer 应用编程

`BPP` 全称是 **Bits Per Pixel**。

每个像素用多少位来表示颜色

`mmap` 全称一般理解为 **memory map**，也常说 **memory-mapped file** 的接口。

在 Linux 里它的意思是：

- 把文件或设备映射到进程地址空间
- 让你像操作内存一样操作它

```
addr = fb_base + y * xres * (bpp / 8) + x * (bpp / 8)
```

`fb_base`：framebuffer 的起始地址

`xres`：屏幕一行有多少个像素

`y`：第几行

`x`：这一行里的第几个像素

`bpp`：每个像素占多少位

`bpp / 8`：每个像素占多少字节

**像素**：屏幕上的一个最小点，颜色单位

**分辨率**：屏幕横向和纵向有多少个像素



`xres` 一般就是 **x resolution**，也就是：

- **横向分辨率**
- 屏幕一行有多少个像素

32BPP：

```
ARGB8888

```

## API函数

打开LCD 设备节点，获取分辨率等参数，映射
Framebuffer，最后实现描点函数。

- ioctl

```
int ioctl(int fd, unsigned long request, ...);
```

> - fd 表示文件描述符；
> - request 表示与驱动程序交互的命令，用不同的命令控制驱动程序输出我们需要的数据；
> - … 表示可变参数arg，根据request 命令，设备驱动程序返回输出的数据。
> - 返回值：打开成功返回文件描述符，失败将返回-1。

- mmap

```
void *mmap(void *addr, size_t length, int prot, int flags,int fd, off_t offset);
```

> - addr 表示指定映射的內存起始地址，通常设为 NULL 表示让系统自动选定地址，并在成功映射后返回该地址；
> - length 表示将文件中多大的内容映射到内存中；
> - prot 表示映射区域的保护方式，可以为以下4 种方式的组合
> - Flags 表示影响映射区域的不同特性

## framebuffer程序分析、

- 获取LCD参数

LCD 驱动程序给APP 提供2 类参数：可变的参数fb_var_screeninfo、固
定的参数fb_fix_screeninfo

```
static struct fb_var_screeninfo var; /* Current var */
if (ioctl(fd_fb, FBIOGET_VSCREENINFO, &var))
{
    printf("can't get var\n");
    return -1;
}
```



> `fd_fb`：前面 `open("/dev/fb0", ...)` 得到的设备句柄
>
> `FBIOGET_VSCREENINFO`：告诉驱动“把当前的可变屏幕参数给我”
>
> `&var`：把结果填到这个结构体里

- 映射framebuffer

要映射一块内存，需要知道它的地址──这由驱动程序来设置，需要知道它
的大小──这由应用程序决定。

```
line_width  = var.xres * var.bits_per_pixel / 8;
pixel_width = var.bits_per_pixel / 8;
screen_size = var.xres * var.yres * var.bits_per_pixel / 8;
fb_base = (unsigned char *)mmap(NULL, screen_size,
                                PROT_READ | PROT_WRITE,
                                MAP_SHARED, fd_fb, 0);
```

screen_size 是整个Framebuffer 的大小；PROT_READ |PROT_WRITE 表示该区域可读、可写；MAP_SHARED 表示该区域是共享的，APP 写
入数据时，会直达驱动程序
