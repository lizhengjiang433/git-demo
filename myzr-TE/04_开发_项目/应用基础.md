# 文件IO

## 分类

标准IO：fopen/fread/fwrite/fseek/fflush/fclose

系统调用IO：open/read/write/lseek/fsync/close

标准IO 的内部，会分配一个用户空间的buffer，读写操作先经过这个
buffer。在有必要时，才会调用底下的系统调用IO 向内核发起操作

`标准 I/O` 由于有用户态缓冲、可能自动刷新、还可能带锁，所以**时延不够确定**，不适合强实时、低延迟、要求确定性的场景

`系统调用 I/O` 更直接，控制粒度更细，**更接近底层**，通常比标准 I/O 更适合需要精细控制的场景

**和内核“连接”的状态在哪里？**

不在用户代码里，而在内核里和 `fd` 里：

- 用户态拿到的是 `fd`
- 内核里会记录这次打开的对象
- 后续 `read(fd, ...)`、`write(fd, ...)` 都通过这个 `fd` 去找对应的内核对象

`open()` 成功后，内核会建立一个“打开文件对象”

# Framebuffer 应用编程

`BPP` 全称是 **Bits Per Pixel**。

每个像素用多少位来表示颜色

`mmap` 全称一般理解为 **memory map**，也常说 **memory-mapped file** 的接口。

在 Linux 里它的意思是：

- 把文件或设备映射到进程地址空间
- 让你像操作内存一样操作它

```
addr = fb_base + y * xres * (bpp / 8) + x * (bpp / 8)
```

`fb_base`：framebuffer 的起始地址

`xres`：屏幕一行有多少个像素

`y`：第几行

`x`：这一行里的第几个像素

`bpp`：每个像素占多少位

`bpp / 8`：每个像素占多少字节

**像素**：屏幕上的一个最小点，颜色单位

**分辨率**：屏幕横向和纵向有多少个像素



`xres` 一般就是 **x resolution**，也就是：

- **横向分辨率**
- 屏幕一行有多少个像素

```

> - fd 表示文件描述符；

> - prot 表示映射区域的保护方式，可以为以下4 种方式的组合
> - Flags 表示影响映射区域的不同特性

# 网络通信

两种传输方式：TCP、UDP

网络协议被分为5层：物理层、链路层、网络层、运输层、应用层

TCP向它的应用程序提供面向连接服务，具有可靠性强、流量控制的特点

UDP对它的应用程序提供无连接服务（不维护连接状态），没有可靠性、流量控制、拥塞控制
